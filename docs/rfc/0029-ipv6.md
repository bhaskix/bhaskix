## Summary

**A second address family, not a second stack.** IPv6 lands as: a parser family in
`bhaskix-net` (fixed header, ICMPv6 with its pseudo-header checksum, neighbour discovery —
pure arithmetic, zero `unsafe`, fuzzed like everything beside it); a `V6` variant on the
`Address` enum RFC 0018 built one-variant on purpose, so the compiler produces the work list;
a link-local address, a neighbour cache and SLAAC in `bin/ipd`; and UDP and TCP over the
**same rings, the same socket capabilities, the same three-leg handover** — because none of
that machinery ever looked inside an address. The ABI carries a v6 endpoint in registers: a
128-bit address is two words, and every socket call has room for two words, a port and a leg
in its four. What does **not** arrive: extension-header processing (refused loudly),
fragmentation (refused loudly — v6 routers do not fragment, and neither do we), DHCPv6,
privacy addresses, and a resolver. Each refusal is written down with a trigger.

## Motivation

**This is the last line of the last open Phase 2 bullet.** The networking row has read "open
for IPv6 alone" since RFC 0027 landed the sockets API on 2026-08-17. Everything else in the
bullet is done and measured.

**The retrofit was pre-paid, and this RFC is the collection.** RFC 0018 §"Address
abstraction" made `Address` an enum with one variant and promised: *"IPv6 then adds a
variant, a parser and a neighbour-discovery mechanism — not a second copy of everything
above it."* Every signature above the parsers already takes `Address`; the routing table is
keyed on it; the socket methods carry it. Either that design decision was worth its cost or
it was ceremony — implementing the second family is the only way to find out, and an
enterprise system that cannot speak the address family of the modern internet has a gap the
README would have to state forever.

**What happens if we do nothing:** the networking bullet stays open, Phase 2 keeps a
permanent asterisk, and the one-variant enum remains an untested claim.

## Design

### The wire code goes where wire code goes: `bhaskix-net`, zero `unsafe`

- **`addr::Ipv6Addr`** — sixteen bytes, wire order, with the derived forms the stack needs:
  the solicited-node multicast address of a unicast address, the EUI-64 interface identifier
  of a MAC, and the multicast MAC of a multicast address (`33:33:` + low four bytes).
  `Address` gains `V6`; the `v4()` accessor's `Option` — written fallible when it had one
  variant, for exactly this moment — starts returning `None` somewhere.
- **`ipv6.rs`** — the fixed header, parse and build: version checked, payload length checked
  against the bytes actually supplied, next header, hop limit. **Extension headers are
  refused, loudly and by policy**: this stack originates none, its peers (NDP, UDP, TCP,
  ICMPv6 echo) need none, and an extension chain is a parser walking attacker-chosen
  lengths — the exact shape of bug this crate exists to refuse. A packet whose next header
  is an extension type is counted and dropped, like every other hostile refusal.
- **`icmpv6.rs`** — the checksum over the v6 pseudo-header (which UDP and TCP borrow — in
  v6 the UDP checksum is mandatory, and a zero checksum is a refusal, not a shrug), echo
  request/reply, and the four neighbour-discovery messages: router solicitation and
  advertisement, neighbour solicitation and advertisement, with the options the stack
  consumes (source/target link-layer address, prefix information) parsed by length and the
  rest skipped by length — the MADT walker's rule, applied to the wire.
- **The fuzz harness grows the family.** Same seeded-mutation loop, same iteration knob;
  the v6 parsers join the corpus the day they exist.

### `bin/ipd`: one neighbour story, two families

The ARP cache generalises to a **neighbour table keyed on `Address`** — one table, one
lifetime discipline, two fill mechanisms (ARP for v4, NS/NA for v6). `ipd` gains, in order:

1. **Link-local identity**: `fe80::` + EUI-64 from the interface MAC, held from the first
   frame. `ipd` answers neighbour solicitations for its addresses with advertisements, and
   answers ICMPv6 echo — the v6 counterpart of the ARP-reply and ping gates that already
   exist. No device work is needed for multicast receive: `netd` programs no RX filter
   today and the emulated device delivers everything; a real NIC's multicast filter is
   named in the hardware-bring-up notes (M1-17), not silently assumed.
2. **SLAAC**: send a router solicitation at bring-up, parse the advertisement, derive the
   global address (prefix + EUI-64), record the default router (the RA's source). The boot
   report prints both addresses and the router the way it prints the v4 lease today —
   and prints honestly when no RA arrives: v6 stays link-local-only, and the machine still
   boots, RFC 0021's rule applied to a different absent luxury.
3. **Dual-stack sockets**: a UDP socket is bound with a family; datagrams are matched the
   way they are matched today. The v4 path does not change shape — the point of the enum
   is that most of `ipd` cannot tell which family it is holding.

### The ABI: a v6 endpoint fits in registers, exactly

An IPC message carries four words. A v6 endpoint is two words of address plus a port —
every socket call fits, none with a word to spare on the widest:

- `BIND_UDP6`, `SEND_TO6` (`arg0`/`arg1` address, `arg2` port), `RECV_FROM6` (reply:
  outcome, address hi, address lo, port — all four words).
- `tcp::CONNECT6` (`arg0`/`arg1` address, `arg2` port, `arg3` leg — exactly four).

Separate method numbers rather than a family flag: a flag would spend a bit of every word
on distinguishing families, and method numbers are what the dispatch already switches on.
`bhaskix-sock` (RFC 0027) grows `Endpoint::V6` and the same calls; the crate is the reason
no program hand-rolls the two-word split.

### `bin/tcpd`: the state machine does not learn what an address is

RFC 0020's segment parser and state machine key connections on
`(Address, Port, Address, Port)` and compute one checksum. The v6 work in `tcpd` is the
pseudo-header and the connection key's type — the handshake, the rings, the three-leg
handover of RFC 0022 and the notification of RFC 0023 are untouched. If step 5 needs more
than the checksum and the key, the one-variant-enum claim was false and the RFC says so.

### The harness, and one reduction stated now rather than discovered

The QEMU lanes gain `ipv6=on` (verified accepted by this tree's QEMU 4.2). slirp provides
router advertisements (`fec0::/64`) and reaches the host at `fec0::2`, so the **outbound**
gates mirror the v4 ones exactly: UDP echo and TCP echo against host listeners bound on
`::`, byte-for-byte, per placement. **Inbound TCP over v6 cannot be exercised on this
QEMU**: slirp's `hostfwd` has no v6 guest-address form until much later QEMU releases. The
LISTEN path is family-blind above the checksum, but a claim needs a wire: the reduction is
stated in the gate list and in TRACKER, with the trigger written — a newer QEMU in CI, or
the first networked hardware boot. Throughput and round-trip are measured the way RFC 0020
step 6 measured v4, and the two families are expected to sit within noise of each other on
the same rings; a gap is a finding, not a footnote.

## What is refused, and when that changes

| Refused | Why | Trigger to build |
|---|---|---|
| Extension headers | This stack originates none and its peers need none; a chain of attacker-chosen lengths is the bug class this crate refuses | A consumer that genuinely needs one (e.g. MLD for a real switch's snooping) |
| Fragmentation (both directions) | v6 routers do not fragment; a send larger than the MTU is refused with both numbers, and inbound fragments are hostile reassembly state | Path-MTU discovery work, driven by a real network that needs it |
| DHCPv6 | SLAAC answers the address question on every network this system can currently reach | A network that withholds RA prefixes (managed-only), met in practice |
| Privacy/stable-random addresses (RFC 4941/7217) | EUI-64 leaks the MAC — acceptable for a system with no privacy story yet, stated rather than hidden | The first deployment where address-derived tracking is a real threat |
| A resolver | Nothing in the system consumes names; both harness peers are numeric | The first consumer of names |

## Alternatives considered

| Alternative | Why rejected | Would reconsider if |
|---|---|---|
| **Defer IPv6 by RFC** (the RFC 0025 pattern) | The bullet names it, the enum was built for it, and the deferral would leave the one-variant abstraction untested — a design claim the project keeps citing but never collected on | If the stack had no pre-paid abstraction, deferral would have been the honest cheap path |
| **A separate `ip6d` domain** | Doubles the hostile-byte surface owners and the socket plumbing for zero isolation gain — both families are parsed by the same crate under the same budget (zero) | A measured reason to scale the families independently |
| **Address as sixteen bytes through the ring instead of registers** | Spends ring-slot format changes on something that fits in registers; the ring carries payload, the message carries addressing — RFC 0018's split | An address family wider than two words |
| **A family flag instead of new method numbers** | Dispatch already switches on method; a flag adds a second axis to every handler's match | Method-number space pressure, which at ~60 of 2⁶⁴ is not close |

## Testing plan

Host tests for every parser and every refusal (the malformed chain, the zero UDP checksum,
the truncated option, the wrong-checksum NA); the fuzz corpus grows the family; the
neighbour table's two fill paths tested against one eviction discipline. Boot gates per
placement: the two v6 addresses and the router printed, a neighbour resolved by NS/NA,
ICMPv6 echo answered, UDP v6 echoed against the host, TCP v6 echoed against the host, and
the v4 gates unchanged beside them — dual stack means both, every boot. The inbound-v6
reduction is a stated gate-list absence, not a silent one.

## Unresolved questions

1. **Which lanes run v6 gates** — all placements, or one lane deep and the rest smoke?
   Decided in step 6 by what the added wall-clock costs; the default position is all,
   because dual-stack regressions hide in the lane that skipped them.
2. **The neighbour table's size and lifetime** — the ARP cache's `8 × 1000` ticks carried
   over, or re-derived for v6's chattier discovery? Decided by measurement in step 3.
3. **`RECV_FROM` unification** — once two families exist, does the v4 reply shape migrate
   to the four-word form so there is one receive path? Deferred until both are green;
   migration is cheap only after the second family proves the shape.

## Implementation plan

1. **The family in `bhaskix-net`**: `Ipv6Addr`, the `V6` variant, the fixed-header parser,
   the pseudo-header checksum, ICMPv6 echo — host tests and fuzz coverage, and the compiler's
   list of every `match` the new variant breaks, resolved honestly rather than `_ =>`'d.
2. **NDP**: the four messages and their options in `bhaskix-net`; the neighbour table
   generalised over `Address` with both fill paths host-tested.
3. **`ipd` speaks v6**: link-local from EUI-64, NS answered, echo answered, SLAAC from the
   RA with the boot report saying what was obtained — first boot gates.
4. **UDP over v6**: the ABI methods, `ipd`'s dual-stack socket table, `bhaskix-sock`'s
   `Endpoint::V6`, and the host-echo gate per placement.
5. **TCP over v6**: the pseudo-header and the connection key in `bin/tcpd`, `CONNECT6`
   through the same three legs, the outbound echo gate — and the inbound reduction stated.
6. **Measurement and the gate ledger**: v6 throughput and round-trip beside v4's numbers,
   the lane decision from question 1, TRACKER's networking row closes the bullet.

Steps 1–2 touch nothing outside `net/`; step 3 is the first boot-visible change; steps 4–5
each ride the existing ring and capability machinery or the RFC fails its own premise.
